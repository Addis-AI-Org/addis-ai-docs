Send a `messages` array to generate a response. The SDK keeps the request shape consistent across single-turn chat, conversation history, instructions, and multimodal input.

<Tabs items={['Node.js', 'Python', 'cURL']} groupId="integration-language">
  <Tab>
```ts
const response = await addis.chat.completions.create({
  persona: "You are a helpful Ethiopian language tutor.",
  system: "Answer in Amharic and include one short example.",
  messages: [{ role: "user", content: "Explain the word እንኳን." }],
});

console.log(response.choices[0].message.content);
```

## Messages, system instructions, and personas

- **[Messages](/docs/core-concepts/messages)** are the conversation. Send prior user and assistant messages again when the next answer needs that context.
- **[System instructions](/docs/core-concepts/system-instructions)** define behavior and constraints for the current request: language, format, tone, or rules.
- **[Persona](/docs/core-concepts/personas)** defines who the assistant is. Keep identity in `persona` and task-specific rules in `system`.

Addis AI continues to enforce platform safeguards and language behavior. Application instructions do not replace those controls.

## Continue a conversation

Append the returned assistant message and the next user message to your stored history. Keep only the history your application needs, and avoid storing sensitive conversations without a retention policy.

## Streaming and files

Set `stream: true` when the SDK consumer should receive long text incrementally. Streaming is for text responses; Addis Voice 2 does not currently stream generated audio.

For images, documents, or audio, use the upload helpers described in [Multimodal](/docs/guides/multimodal). To let the model request application actions, continue to [Function Calling](/docs/core-concepts/function-calling).
