Realtime Audio is a stateful WebSocket experience, separate from Voice 2 clip generation. Your authenticated application must obtain a short-lived user JWT before opening the relay connection. Never put an Addis API key in browser or mobile code.

## Session flow

1. Obtain a short-lived user JWT through your authenticated application.
2. Connect to `wss://relay.addisassistant.com/ws?jwt=...`.
3. Wait for `{ "setupComplete": true }`.
4. Capture mono PCM16 audio at 16 kHz.
5. Send `{ "data": "<base64>", "mimeType": "audio/pcm;rate=16000" }` messages.
6. Decode returned 24 kHz PCM from `serverContent.modelTurn.parts[0].inlineData`.
7. Stop queued playback when `serverContent.interrupted` is true.
8. Record `usageMetadata` when a turn completes and close the socket cleanly.

Implement bounded reconnection, ordered playback, microphone permission handling, audio backpressure, and explicit interruption behavior. Realtime is Beta and its event contract may change independently of the REST SDKs.

See the [Realtime WebSocket event reference](/docs/reference/realtime).
