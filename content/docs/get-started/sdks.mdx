The clients read `ADDIS_API_KEY` from the environment by default. Python currently provides a synchronous client; do not assume an async client is available.

## Keep keys on your server

Never embed an Addis AI API key in browser JavaScript, a mobile application, or a public environment variable. Your frontend should call a route you own; that route authenticates the user and calls Addis AI.

```text
Web or mobile app → your authenticated backend → Addis AI SDK → Addis AI API
```

Create one SDK client per server process, validate user input, apply per-user limits, and return only the response fields the frontend needs. Use idempotency values for billed voice generation.

### A protected server route

Authenticate the caller before forwarding a validated prompt. This route keeps the Addis key outside the browser and limits the response returned to the client.

<Tabs items={['Node.js', 'Python']} groupId="server-language">
  <Tab>
```ts
import AddisAI from "addisai";

const addis = new AddisAI();

export async function answer(userId: string, prompt: string) {
  await authorize(userId, "chat:create");
  if (!prompt || prompt.length > 4_000) throw new Error("Invalid prompt");

  const response = await addis.chat.completions.create({
    messages: [{ role: "user", content: prompt }],
  });
  return { text: response.choices[0].message.content };
}
```
  </Tab>
  <Tab>
```python
from addisai import AddisAI

addis = AddisAI()

def answer(user_id: str, prompt: str):
    authorize(user_id, "chat:create")
    if not prompt or len(prompt) > 4_000:
        raise ValueError("Invalid prompt")

    response = addis.chat.completions.create(
        messages=[{"role": "user", "content": prompt}],
    )
    return {"text": response["choices"][0]["message"]["content"]}
```

### Web, mobile, and voice applications

Web and mobile clients should authenticate to the same backend boundary. Apply tenant quotas, request timeouts, safe logging, and CSRF protection where applicable. Assume mobile binaries can be inspected and never rely on hiding a permanent API key inside the app.

A turn-based voice agent composes three resources:

```text
audio → speech.transcribe → chat.completions.create → voice.generate → audio clip
```

Use a stable client request ID for voice retries. For bidirectional low-latency sessions, use [Realtime Audio](/docs/guides/realtime), currently Beta.
