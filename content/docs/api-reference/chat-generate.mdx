Use this endpoint for chat, summarization, extraction, RAG, structured output, and function calling. The SDKs wrap it as `addis.chat.completions.create`; see the [Text Generation guides](/docs/capabilities/text-generation).

## Request parameters
These parameters go in the root of your JSON body.

<TypeTable
  type={{
    'prompt': {
      description: 'The user input text or question.',
      type: 'string',
      required: true
    },
    'target_language': {
      description: 'Output language code. Use "am" for Amharic or "om" for Afaan Oromo.',
      type: 'string',
      required: true
    },
    'conversation_history': {
      description: 'Array of previous message objects to maintain context.',
      type: 'array',
      default: '[]'
    },
    'persona': {
      description: 'Optional plain-text assistant identity. It shapes voice and role, for example: "You are a patient Ethiopian language tutor." Use system for behavior and constraints.',
      type: 'string',
      required: false
    },
    'system': {
      description: 'Optional plain-text behavior, language, constraint, or output instruction, for example: "Answer in Amharic, then include one short English gloss." It guides behavior above user messages; platform safeguards always remain in force.',
      type: 'string',
      required: false
    },
    'generation_config': {
      description: 'Configuration object for model behavior (see below).',
      type: 'object',
      default: '{}'
    }
  }}
/>

## Generation config
Use `generation_config` to tune the creativity and length of the response.

<TypeTable
  type={{
    'temperature': {
      description: 'Controls creativity (0.0 to 1.0). Use 0.2 for factual Q&A, 0.7 for creative writing.',
      type: 'number',
      default: '0.7'
    },
    'maxOutputTokens': {
      description: 'Limit the maximum length of the response.',
      type: 'number',
      default: '1024'
    },
    'topP': {
      description: 'Nucleus sampling probability.',
      type: 'number',
      default: '0.9'
    },
    'topK': {
      description: 'Top-K sampling parameter.',
      type: 'number',
      default: '40'
    }
  }}
/>

## Response
The API returns a JSON object.

```json
{
  "response_text": "The generated text response...",
  "finish_reason": "stop",
  "usage_metadata": {
    "prompt_token_count": 12,
    "candidates_token_count": 45,
    "total_token_count": 57
  },
  "modelVersion": "Addis-፩-አሌፍ"
}

```
<TypeTable
type={{
'response_text': {
description: 'The main output text generated by the model.',
type: 'string'
},
'finish_reason': {
description: 'Why the generation stopped. One of "stop" (natural end), "length" (maxOutputTokens reached), "content_filter" (blocked by safety filters), "tool_calls" (the model requested a tool) or "other". Streaming responses use the same values.',
type: 'string'
},
'usage_metadata': {
description: 'Token usage for billing: prompt_token_count, candidates_token_count and total_token_count. Streaming responses report the same three fields.',
type: 'object'
},
'modelVersion': {
description: 'The Addis AI model that produced the response.',
type: 'string'
},
'tool_calls': {
description: 'Present when the model requests tools. Each item has id, type, function.name, function.arguments (a JSON string) and addis_tool_state, an opaque token: return the tool call unchanged in the assistant message of your next request, and never parse or edit the token.',
type: 'array'
},
'uploaded_attachments': {
description: 'Present when the request uploaded files. Each item has fileUri, an opaque Addis file reference ("addis://files/<id>"), and mimeType. Send fileUri back unchanged as fileData.fileUri to reuse the file.',
type: 'array'
}
}}
/>
<Callout type="info" title="Token Counting">
Token counts vary by language, script, punctuation, and input structure. For Amharic, one word typically uses around 1.5 to 1.8 tokens. For the exact count, use usage_metadata returned in the REST API response or the corresponding usage value returned by the official SDK.
</Callout>
