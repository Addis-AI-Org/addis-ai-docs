The production chat API can return structured `tool_calls`, but the currently published SDKs cannot complete the tool-result round trip reliably. Function calling remains Beta and is not ready for production workflows. Tool calling is non-streaming.

<Callout type="warn" title="Published SDK limitation">
Live verification on 2026-07-17 found that `runTools` in Node `0.1.2` and `run_tools` in Python `0.1.1` can repeat a completed call until their round limit. Node `0.1.2` also drops assistant tool-call messages and tool results after the last user message when it maps a follow-up request; Python `0.1.1` cannot return the completed result correctly either. Do not execute tools or attempt a manual result loop with these package versions.
</Callout>

## Inspect a structured call in development

The following receive-only examples are useful for evaluating schemas. They intentionally stop before executing the requested function.

<Tabs items={['Node.js', 'Python', 'cURL']} groupId="integration-language">
  <Tab>
```ts
const tools = [{
  type: "function" as const,
  function: {
    name: "get_weather",
    description: "Get current weather for an allowed city",
    parameters: {
      type: "object",
      properties: { city: { type: "string" } },
      required: ["city"],
    },
  },
}];

const response = await addis.chat.completions.create({
  language: "am",
  messages: [{ role: "user", content: "Use get_weather for Addis Ababa." }],
  tools,
  tool_choice: "required",
});

const call = response.choices[0].message.tool_calls?.[0];
if (!call) throw new Error("The model did not request a tool");
console.log(call.function.name, JSON.parse(call.function.arguments));
```
  </Tab>
  <Tab>
```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Get current weather for an allowed city",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        },
    },
}]

response = addis.chat.completions.create(
    language="am",
    messages=[{"role": "user", "content": "Use get_weather for Addis Ababa."}],
    tools=tools,
    tool_choice="required",
)

calls = response["choices"][0]["message"].get("tool_calls", [])
if not calls:
    raise RuntimeError("The model did not request a tool")
print(calls[0]["function"]["name"], calls[0]["function"]["arguments"])
```

## Release requirement

A production guide will be added only after coordinated Node and Python releases preserve the complete assistant message, opaque tool state, `tool_call_id`, and tool result, and both automatic helpers pass a live bounded-round test. Until then, use ordinary application code outside the model loop for actions that require authorization or side effects.

## Security requirements

1. Define narrow JSON schemas and reject unexpected properties.
2. Treat arguments and tool output as untrusted input.
3. Authorize each action for the authenticated user and tenant.
4. Apply timeouts, maximum rounds, and idempotency to side effects.
5. Require human approval for payments, deletion, messages, or other consequential actions.
6. Never expose arbitrary database, filesystem, network, or shell access as a tool.
