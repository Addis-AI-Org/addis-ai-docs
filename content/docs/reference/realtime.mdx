<StatusBadge status="beta">Beta</StatusBadge>


Connect to `wss://relay.addisassistant.com/ws` with an Addis API key in the case-sensitive `apiKey` query parameter:

```text
wss://relay.addisassistant.com/ws?apiKey=<addis-api-key>
```

The relay also accepts a Supabase user JWT for the signed-in Addis developer portal. That first-party portal session is not the public developer authentication flow. Third-party server integrations should use their Addis API key.

Browser WebSocket clients cannot set the `x-api-key` header. Direct browser use therefore exposes the key to the browser runtime and WebSocket upgrade URL; use it only for development testing. Production browser and mobile applications should connect through a WebSocket proxy that keeps the Addis key server-side.

Send mono 16-bit PCM audio at 16 kHz as base64-encoded JSON messages:

```json
{ "data": "<base64-pcm16>", "mimeType": "audio/pcm;rate=16000" }
```

The relay confirms readiness with:

```json
{ "setupComplete": true }
```

Model audio is returned as 24 kHz PCM in `serverContent.modelTurn.parts[0].inlineData`. A completed turn may include `serverContent.turnComplete` and `usageMetadata`. Stop queued playback when `serverContent.interrupted` is true. Warning messages use `{ "type": "warning", "message": "..." }`; failures use `error`.

This Beta protocol can change. Keep authentication, audio conversion, event parsing, reconnection, and playback scheduling behind an application adapter.
