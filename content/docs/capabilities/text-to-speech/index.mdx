Addis Voices 2 turns Amharic, Afaan Oromo, Tigrinya, Swahili, Hausa, Sidama and Wolaytta text into durable audio clips. It is billed by generated duration at **5 ETB per minute**. Use `voice.generate` for completed clips in every language, or follow [Streaming text-to-speech](/docs/capabilities/text-to-speech/streaming) for HTTP streams and persistent WebSocket sessions in every one of these languages.

## Discover voices

Query the catalog rather than copying an arbitrary ID into production configuration. `am-hamen` is the canonical Amharic example, `om-bikila` the Afaan Oromo one, `ti-berhane` the Tigrinya one, `sw-rashid` the Swahili one, `ha-mustapha` the Hausa one, `sid-tigist` the Sidama one and `wal-tona` the Wolaytta one.

The catalog is dynamic. Filter for the requested language and store only IDs currently marked available. Each entry includes the voice ID, name, descriptor, language, gender, style, tags, preview URL, default status, and availability.

### Catalog filters

| Filter | Node.js | Python | Values |
| --- | --- | --- | --- |
| Language | `language` | `language` | `am`, `om`, `ti`, `sw`, `ha`, `sid`, or `wal` |
| Gender | `gender` | `gender` | `female` or `male` |
| Search | `search` | `search` | Name, ID, descriptor, style, or tag text |
| Include unavailable voices | `includeUnavailable` | `include_unavailable` | `false` by default |

## Batch generation

Send up to 10,000 text-to-speech requests in one batch. Batches run off-peak, every batch finishes within 24 hours, and only finished requests are billed, at **2.5 ETB per generated minute**, half the Voices 2 list price. Batches accept Amharic (`am`), Afaan Oromo (`om`), Tigrinya (`ti`), Swahili (`sw`), Hausa (`ha`), Sidama (`sid`) and Wolaytta (`wal`) with the same voices as `voice.generate`. Each request's voice ID must match its language; the SDK rejects any other language, or a voice ID from another language, before uploading. Swahili, Hausa, Sidama and Wolaytta need SDK 0.13.0 or later.

Any account with at least one paid top-up can create batches; signup credit alone does not count. Create them with the SDK methods below (Node.js or Python SDK **0.9.0** or later), or upload a CSV on the Batches page of the dashboard.

<Tabs items={['Node.js', 'Python']} groupId="integration-language">
  <Tab>
```ts
const batch = await addis.batches.createFromRequests({
  requests: chapters.map((text, index) => ({
    customId: `chapter-${index + 1}`,
    text,                 // e.g. "ሎሚ ጽቡቕ መዓልቲ እዩ።"
    voiceId: "ti-berhane",
    language: "ti",
  })),
  metadata: { project: "audiobook" },
});

const done = await addis.batches.waitFor(batch.id); // polls every 30 s
for await (const result of addis.batches.results(done.id)) {
  if (result.status === "succeeded") {
    const audio = await addis.files.content(result.response!.audioFileId);
    // save audio
  } else {
    console.warn(result.customId, result.error);
  }
}
```
  </Tab>
  <Tab>
```python
batch = addis.batches.create_from_requests(
    [
        {"custom_id": f"chapter-{i}", "text": text, "voice_id": "ti-berhane", "language": "ti"}
        for i, text in enumerate(chapters, start=1)
    ],
    metadata={"project": "audiobook"},
)

done = addis.batches.wait_for(batch["id"])  # polls every 30 s
for result in addis.batches.results(done["id"]):
    if result["status"] == "succeeded":
        audio = addis.files.content(result["response"]["audio_file_id"])
        # save audio
    else:
        print(result["custom_id"], result["error"])
```
  </Tab>
</Tabs>

Already have a JSONL file with one `{"custom_id": "...", "body": {...}}` per line? Upload it with `files.upload` and pass its ID to `batches.create`. `batches.cancel` stops queued requests; running ones finish and are billed.

## Output formats

| Format | Use |
| --- | --- |
| `mp3_44100` | Compact delivery for web, mobile, and downloads. |
| `wav_44100` | Uncompressed editing and audio pipelines. |
| `pcm_16000` | Speech pipelines expecting 16 kHz PCM in a WAV container. |

Choose the format before estimating because output choice can affect generated duration and storage behavior.

## Idempotency and retries

`clientRequestId` in Node.js and `client_request_id` in Python identifies one logical generation.

- Reuse it when retrying the same request after a timeout or uncertain response.
- Generate a new value for different text, voice, language, or output format.
- Do not retry a validation error unchanged.
- For a generation-in-progress response, wait for the reported retry interval before checking again.

## Voice settings

`speed` is currently applied. `stability`, `similarity`, and `style` are accepted for compatibility but ignored by the current provider. The response reports ignored settings in `meta.ignoredVoiceSettings` or `meta["ignored_voice_settings"]`.

Do not build user-facing behavior that assumes an ignored control changes the generated clip.

## Errors

Common failures include unavailable voice IDs, unsupported formats, insufficient balance, idempotency conflicts, generation still in progress, rate limiting, and transient provider errors.

Refresh the voice catalog after an unavailable-voice error. Log the clip ID, request ID, and client request ID, but never the API key or sensitive full text.

## Migrate from Legacy Text-to-Speech

Addis Voices 2 uses the same Addis AI API key as the legacy API, so no credential migration is required. HTTP header names are case-insensitive: the SDK reads `ADDIS_API_KEY`, and raw requests send it through `x-api-key`.

| Area | Legacy Text-to-Speech | Addis Voices 2 |
| --- | --- | --- |
| Endpoint | `/api/v1/audio` | `/api/v1/voice/generations` |
| Authentication | Existing Addis AI API key in `X-API-Key` | The same API key through the SDK or `x-api-key`; no credential change |
| Request | `text`, `language`, and optional `stream` | `text`, `voice_id`, `language`, `output_format`, and optional `client_request_id` |
| Voice selection | Language selects the legacy engine | Query the [voice catalog](#discover-voices), preview an available voice, then send its exact ID |
| Response | Base64 WAV JSON or a legacy audio stream | Durable clip metadata and a signed `audio_url`; [HTTP and WebSocket streaming](/docs/capabilities/text-to-speech/streaming) are also available |
| SDK | `legacy.audio.generate()` or `legacy.audio.stream()` | `voice.generate()`, `voices.list()`, estimates, usage, and clip management |
| Pricing | Existing Voice 1 account pricing remains unchanged | **5 ETB per generated minute**, with a pre-generation estimate |

For a new integration, follow [Generate and save a clip](#generate-and-save-a-clip). Existing applications can keep using the complete [Legacy Text-to-Speech guide](/docs/capabilities/text-to-speech-legacy) while migrating one use case at a time. Review [Pricing](/docs/platform/pricing) before switching production traffic.
